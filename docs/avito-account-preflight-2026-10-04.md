# Avito: Read-only Проверка Аккаунта

## Повторная Сверка Перед Активацией

После успешной проверки XML выполнена новая read-only сверка: timestamp
ответа `2026-10-04T23:38:26.924607+03:00`. Авторизация/self успешны;
профиль и оба ID-link метода по-прежнему возвращают 403. Перечисление
всех пяти статусов полное: одно old-объявление `8312555394`, активных нет.

Отдельный GET деталей подтвердил status=old и отсутствие autoload_item_id.
Точная связь с пилотными Id не установлена. Контракт предоставленного API
деталей не содержит описания, фото или серийных идентификаторов; метод не
позволяет восстановить SKU по содержимому карточки. Не считать отсутствие
autoload_item_id доказательством отсутствия физического пересечения.
Не присваивать AvitoId по цене 47 599 ₽.

Владелец предоставил скрин «Переход на загрузку по ссылке»: одно видимое
пустое поле URL, нет заполненных периодов, текст описывает загрузку каждый
час. Это форма перехода, а не подтверждённый снимок сохранённого профиля:
существующие загрузки файлом/URL и состояние автозапуска неизвестны.
Не объявлять feeds_count=0 и не нажимать «Сохранить» до согласованного запуска.
Видимая подсказка о пяти ссылках относится к этому интерфейсу.

Владелец затем явно подтвердил: форма не сохранена, действующей автозагрузки
и других сохранённых URL нет. Операторский вопрос об исходных источниках
закрыт этим подтверждением; API-доступ к профилю всё ещё не подтверждён.
Новую ссылку не сохранять до разрешённого запуска пилота.

Добавлен `listing_details_summary` в read-only клиент: возвращает только
внешний номер, статус, наличие URL/Id и точное совпадение с заданными
публичными Id пилота. Неизвестные исторические Id, URL, тексты и контакты
не экспортируются. another_user/not_found не считаются подтверждённой связью.
Проходят 19 тестов клиента, включая четыре новых теста деталей.

Свежий каталог сохранён в `preactivation-catalog-snapshot.json`, API-сверка
в `preactivation-account-preflight.json` рядом с пилотными артефактами.
Подготовка отдельно пересобрана в подпапке `preactivation/`: т11/т29/т12,
цены 57 900 / 51 599 / 57 900 ₽, остаток каждого 1; selected facts unchanged.
XML совпадает побайтово с прежним входом валидатора. Production и Avito
не изменялись. Проверка сохранённых источников и исторической карточки
остаётся операторской задачей, не обходится через запрещённые браузерные пути.

Владелец позже подтвердил, что старое объявление неактивно и активировать
его не будет. Для текущего пилота принято решение оставить его без изменений
и не включать в выгрузку. Это снимает необходимость предварительно определить
его SKU для этих трёх новых позиций, но не подтверждает складскую идентичность
и не разрешает присвоить AvitoId новому товару. Будущая реактивация потребует
точной сверки. Свежий публичный preflight прошёл 3 страницы / 3 сертификата /
18 JPEG; XML неизменен. Разрешение на публикацию ещё не получено.

API вернул одно объявление: `8312555394`, `old`, цена 47 599 ₽, категория 84.
Активных объявлений нет в доступном этому аккаунту списке. Метод по контракту
ограничен владельцем объявлений, поэтому это не аудит объявлений всех сотрудников.
Детали этого объявления доступны, `autoload_item_id` отсутствует. Оно не

этому же аккаунту или ещё доступно API. Новые объявления не создавались.

403 профиля не означает неисправность Client ID/Secret: token, self и items
работают. Причина 403 из безопасного кода ответа не установлена: проверить
подключение автозагрузки и доступ API в кабинете/поддержке. Расширенный тариф
сам по себе не является доказательством доступности конкретного метода.
Чтение документации категорий также не доказывает доступ к публикации.

Владелец затем подтвердил доступность в кабинете загрузки файлом и по ссылке.
Для первого пилота выбирается подключение URL оператором в кабинете после QA.
403 профиля API не блокирует этот путь, но остаётся ограничением API-управления.
Доступность интерфейса пока не означает принятие XML. Существующие источники,
расписание и условия публикации перед подключением нужно проверить в кабинете;
доступа через API для этой сверки сейчас нет. Настройки не менялись.

## Подтверждённая Категория

Дерево: Электроника → Телефоны → Мобильные телефоны.
`node_slug=mobilnye_telefony` получен из API, не из внутреннего slug сайта.

- `Category=Телефоны`, `GoodsType=Мобильные телефоны` — обязательные XML-поля,
  каждое имеет одно значение. Это снимает прежнюю неопределённость GoodsType.
- `AdType=Товар приобретен на продажу` присутствует в официальных значениях.
  `Condition` принимает `Новое` или `Б/у`.
- `Vendor`, `Model`, `MemorySize`, `Color`, `RamSize` обязательны, `is_catalog=true`.
  Их сочетания не подтверждены: ответ не содержит конкретных допустимых
  значений и ссылок values_link_json/xml для этих каталожных полей.
- `SimConfig` необязателен: SIM + eSIM, 2 SIM, 1 SIM, Только eSIM, Не знаю.
  Не выводить региональную конфигурацию из названия модели.
- `Set` необязателен и имеет checkbox-семантику: Коробка, Блок зарядки,
  Провод зарядки. Окончательная XML-структура многозначного поля ещё не
  подтверждена; в текущем генераторе оно не сериализуется.
- `BoxSealed` доступен, когда `Set` содержит Коробка, и тогда обязателен.
  Отправка без соответствующего Set требует отдельной проверки/исключения.
- `Akb` необязателен, доступен для Apple, integer 0-100. ISVOI намеренно
  требует его для своего пилота Apple с пробегом как контентную политику.
- `ScreenCondition` и `CaseCondition` обязательны. Их значения подтверждают
  текущие ограниченные списки генератора, но не фактическое состояние товара.
- У `DeviceFlaws` API одновременно вернул select/string и input/integer
  правила без dependencies. Не расширять сериализацию по догадке; окончательный
  пилот должен пройти XML-проверку и проверку кабинетом.

`AVITO_PHONE_SCHEMA_VERIFIED` остаётся выключенным. Получение списка тегов
не подтверждает все каталожные сочетания, условия и принятие XML аккаунтом.
