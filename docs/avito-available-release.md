# Avito: 12 постоянных ID, 11 устройств в наличии

Партия от 12.10.2026 добавляет только т20, т39 и т18. Девять ранее
зарегистрированных ID сохраняются, но проданный т11 остаётся вне фида.
Нельзя восстанавливать его по положительному историческому snapshot склада.

Проверенный владельцем XML содержит 11 объявлений / 64 JPEG. SHA-256:
`b90f6f21bf99356b474090f15d13f895c25d808984a4ebda7ccba388291f88d7`.
Исходный живой фид: 8 объявлений / 46 JPEG; SHA-256:
`8c87691cfc96df6a7cacc27afa7bace63ec91bc005255164769bf9cea7ed4fec`.

## Контракт

`prepare_avito_available_release.py` закрепляет 12 конкретных канальных
записей, цены, складские связи, даты диагностики и фото. План включает проданный
т11 для контроля его неизменности, но публичные проверки и XML включают только
11 доступных устройств. Изменить можно ровно три новых канальных записи.

У т39 грейд B и «Мелкие царапины» корпуса; точные нюансы сохраняются в тексте.
У т18 грейд B только из-за батареи, корпус «Без дефектов». Нельзя нормализовать
эти данные до грейда A или менять даты отчётов ради проверки Avito.

## Выкат

1. Свежие read-only source/public проверки, план не старше часа; проверенный
   backup базы и uploads моложе суток. Секреты и полные идентификаторы не вывозить.
2. Подтверждение валидатора относится к точному XML. Отдельные authorization
   и stability receipts относятся к этой партии; прежний отказ от ожидания
   не наследуется. Дополнительные платные услуги не включать.
3. `python scripts/test_avito_expansion_sql.py --available` проверяет отдельный
   `postgres:16-alpine --network none`. Затем production dry-run и write rehearsal
   с `ROLLBACK`; реальные товары, цены, остатки, фото и mapping не меняются.
4. Выкатить код с лимитом 12, пока env и PM2 сохраняют прежние 9 ID.
   Isolated build, `/trade` и точный исходный восьмистрочный фид проверяются
   до замены `.next`; рестартуется только `isvoi-web`.
5. `activate_avito_available_batch.py --apply --confirm-publication` требует
   plan/XML, свежий backup, authorization и stability. Оператор меняет ровно
   три канальные записи. Receipt: `avito-eleven-available-receipt.json` в backup.
6. Расширить только allowlist до 12 ID в env и PM2 через `--update-env`.
   Фид должен содержать ровно 11 ID, не т11. Сравнить по именам полей:
   текст, цену и порядок фото; проверить no-store/noindex, smoke, health, PM2 save.

## Откат

Сначала вернуть allowlist к прежним 9 ID и проверить восьмистрочный фид.
При отдельном разрешении на откат использовать этот же оператор с
`--rollback --confirm-publication`, свежим backup и исходным receipt.
Возвращаются только owned-поля трёх новых записей в draft; чужие заметки
сохраняются. Оператор отказывает при последующих изменениях owned-полей.

Подключённая автозагрузка сама получает живой URL. Наличие в фиде не доказывает
успешную модерацию или размер расходов: отчёт кабинета проверяется отдельно.
Исторические pilot/six/nine операторы для этой партии не использовать.
