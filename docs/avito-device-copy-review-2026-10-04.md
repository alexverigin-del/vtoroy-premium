# Avito: Описания Устройств

Дата сверки: 2026-10-04. Это редакторские предложения, не разрешение на
публикацию. Directus, сайт и объявления Avito в этой итерации не изменялись.

## Источники

- Предоставленный владельцем `444312638_2026-10-04T17_25_00Z.xlsx`, лист
  `Телефоны-Мобильные телефоны`, G5 (название) и H5 (описание). Историческое
  объявление, не актуальное предложение магазина. Workbook содержит контакты
  и полный IMEI в других полях; он не коммитится и не копируется в отчёт.
- Read-only production Directus/PostgreSQL: products, device_details,
  device_passports, текущие device_diagnostic_reports, inventory_items,
  inventory_receipt_lines и опубликованный store_locations/belgorod.
- Контекст продукта: PRODUCT.md; доказательства API и допуска пилота:
  [Account Preflight](avito-account-preflight-2026-10-04.md).

H5 содержит HTML и около 1 846 символов видимого текста. Новые описания
готовятся как обычный текст: HTML не нужен текущему генератору фида.
Цена и остаток остаются структурированными полями, чтобы текст не расходился
с ними при обновлении. SKU и технические блокеры не включаются в Description.

## Варианты Подачи

1. **Короткий.** Модель, состояние, батарея с датой отчёта, комплект, гарантия,
   Passport и приглашение на просмотр. Подходит для быстрого сканирования.
2. **Сбалансированный, рекомендуемый.** Те же сведения плюс конкретные группы
   функциональных проверок и аккуратная формулировка оригинальности компонентов.
   Покупатель видит, чем подтверждено состояние, без длинной рекламы магазина.
3. **Passport-first.** Сразу после названия поставить диагностику NSYS и её дату,
   затем батарею, состояние, комплект и гарантию. Подходит для акцента на проверках;
   возможное влияние на конверсию пока не измерено.

Все три варианта для каждого кандидата сохранены локально в
`outputs/avito-pilot-2026-10-04/description-proposals.json`.
Владелец выбрал и одобрил сбалансированные описания 04.10.2026.
В `outputs/avito-pilot-2026-10-04/selected-channel-copy.json` сохранены три
выбранных текста для существующего поля `product_channel_listings.description_override`.
Генератор уже использует это поле прежде общего описания товара; менять
`products.short_description` или frontend для выбора варианта не требуется.
Файл служит локальной подготовкой, не исполняемым импортом. Его метаданные и SKU
не являются полями для PATCH Directus. Одобрено только содержание Description,
не названия, складской допуск, запись в production, активация фида или публикация.

## Ограничения Достоверности

- Батарея и циклы взяты из отчётов августа, не измерены заново 4 октября.
  Перед подключением фида перепроверить актуальность состояния. 0 циклов не
  доказывает, что телефон новый или батарея не менялась.
- Не переносить заводской IP68 в обещание влагозащиты устройства с пробегом.
  Отсутствие следов жидкости по доступной диагностике не доказывает отсутствие
  контакта с водой за всё время эксплуатации.
- Оригинальность проверенных компонентов не означает отсутствие всех ремонтов
  в истории. Не писать «не ремонтировался» без отдельного доказательства.
- Комплект подтверждён как устройство, коробка, кабель. Блок питания не заявлен.
- Заголовки короче 50 символов. Описания короче 7 500 символов, без HTML,
  IMEI, serial, QR, закупки, маржи, внутренних заметок и вымышленных условий.
  Это локальная проверка текста, не результат приёмки XML кабинетом Avito.

## Продолжение Пилота

У т37 `identity_status=unmatched`: серийный номер на складе присутствует,
но загруженные поступления не содержат точного совпадения по serial,
связанных receipt-строк нет; IMEI складской строки не заполнен.
Это не доказанный конфликт идентичности. Открытых issue-строк нет, однако
отсутствие issue не снимает строгий identity guard. Статус не изменялся.

Следующие действия:

1. Вариант текста выбран; перед запуском оператор подтверждает актуальность диагностики.
2. Сверить первичный приход т37 по внутреннему идентификатору и serial либо
   отдельно согласовать замену кандидата. Не переводить в matched автоматически.
3. Подтвердить каталожные значения Avito и условные XML-поля, сопоставить старое
   объявление, заполнить category mapping и профиль расходов оператора.
4. После отдельного разрешения на изменения выполнить выкат, подготовить XML
   и подключить URL в кабинете с проверкой действующих источников и расписания.

До этих действий все канальные объявления остаются draft, фид выключен.
HTTP 403 профиля API не блокирует согласованный путь через URL в кабинете.
