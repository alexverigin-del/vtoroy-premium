### Операторский Rollout

`scripts/activate_avito_pilot.py` выполняется на VPS с исходным согласованным XML
и `--backup-dir` внутри `/opt/isvoi/backups`. По умолчанию это dry-run;
`--rehearsal` проверяет запись и восстанавливает исходное состояние в одной
транзакции. `--apply` проверяет SHA256SUMS свежего backup, сохраняет before-state
и обновляет только три существующие канальные записи. `--rollback` восстанавливает
только поля, которыми владеет этот rollout, и отказывается затирать последующие
операторские правки. Полный backup базы не восстанавливается ради отката пилота.

Новый mapping `smartphones-pilot-2026-10-04` не заменяет default mappings.
Канальный `active` означает допуск к XML, а не публикацию на Avito.
Изменения в кабинете и запуск автозагрузки требуют отдельного подтверждения.

## Сверка Старого Объявления

Объявление `8312555394` не связано с подтверждённым складским SKU.
На последнем GET нет активных объявлений, но это не закрывает вопрос дублей
и последующего восстановления старого объявления при автозагрузке.

Для точной связи использовать известный исторический XML Id, документы
или подтверждённые приватные идентификаторы устройства. Сверять их в
защищённом контуре; не присылать полный IMEI/serial в публичном отчёте.
Совпадение модели/цены/цвета — только подсказка. Внешний номер Avito и XML Id
не взаимозаменяемы. Ответ 403 ID-link API не означает отсутствие связи.

Если устройство установить нельзя, вопрос остаётся открытым. Не назначать
AvitoId ни одному из пилотных товаров, не удалять и не изменять старое объявление.

Владелец затем подтвердил: старое объявление неактивно и активировать его
не планирует. Операторское решение для текущего пилота принято: оставить
его без изменений, исключить из пилота, не связывать ни с одним новым SKU.
Точное определение старого SKU больше не является условием запуска этих
трёх новых объявлений. Это не техническое подтверждение идентичности;
при будущем восстановлении/миграции старого объявления точная сверка
потребуется вновь. Решение не разрешает публикацию нового пилота.

Повторный GET деталей: старое объявление остаётся old, autoload_item_id
отсутствует. Этот контракт не возвращает описание/фото. Для дальнейшей
ручной сверки нужен экран самой карточки; название или фото являются
подсказкой, а не автоматическим подтверждением полного складского ключа.

## Будущий Запуск После Отдельного Разрешения

1. Завершить кабинетное QA и подтвердить сохранённые источники/расписание;
   сохранить решение владельца не активировать старое объявление;
   получить явное разрешение на production-изменения и публикацию пилота.
2. Сделать VPS backup перед записью Directus, повторить snapshot и HTTP/JPEG
   проверки, пересобрать подготовку. Изменение stock/цены/фото/Passport требует
   новой проверки; одобрение текста не переносится на изменённые факты.
3. Применить только три согласованных канальных записи и подтверждённый mapping,
   сохранив перечисленные Id. Не менять другие объявления и не добавлять т37.
4. Провести repo gates и выкат. Только после подтверждённого формата установить
   schema gate; feed gate и разрешённые Id активировать для согласованного запуска.
   Без этого endpoint должен оставаться закрытым. Комплект/BoxSealed в XML
   не добавлять без отдельной проверки зависимого контракта.
5. Подключить согласованный источник через кабинет, сохранив остальные источники.
   Запуск API upload не ограничивается тремя объявлениями из этого фида и
   может обработать другие файлы профиля; его не использовать как тест.
6. Зафиксировать результат именно этой загрузки по upload_id и каждому Id,
   проверить ошибки, внешний статус/URL и фотографии. Обработка файла не
   равна публикации: дождаться модерации и сверить карточки.
7. После 72 часов без рассинхронизации решать вопрос расширения пилота.
   Продажа и снятие объявления должны проверяться отдельно; отсутствие
   товара в XML само по себе не доказывает снятие объявления на Avito.

Этот документ не выдаёт разрешение на включение фида, загрузку или платные операции.
