## Локальный XML-пример

Следующая read-only сверка получила полные документы Set/BoxSealed/DeviceFlaws
через API категории; результат — `phone-xml-field-details.json`. Официальную
страницу шаблона браузерный инструмент не открыл; обход через shell или другой
браузер не выполнялся.

У Set подтверждены необязательность и checkbox/string, но нет конкретного
XML-представления списка. BoxSealed зависит от Set=Коробка; дополнительный
текст упоминает новую технику. Для первого минимального примера оба поля
опущены, подтверждённый комплект остаётся в описании. Открытая коробка
по-прежнему отражена в XLSX. Не вводить вымышленные дочерние теги Set и
не отправлять BoxSealed отдельно от него. SIM/IMEI/AvitoId также опущены.

Подготовлены `ISVOI_Avito_SCHEMA_REVIEW_2026-10-04.xml` и
`xml-review-manifest.json`. Ровно три позиции, стабильные Id/цены, по шесть
JPEG. XML имеет комментарий NOT APPROVED FOR UPLOAD и только публичные поля.
Manifest явно различает well-formed XML, неподтверждённую официальную схему,
справочные сочетания и фактическое принятие кабинетом. **Не загружать этот
пример и не подключать его как фид до QA и отдельного согласования.**

Позднее владелец показал отдельную справочную страницу Avito «Проверить файл»
для XML v.3. XML-пример допускается передать именно в этот валидатор для
проверки формата, не в публикационную автозагрузку. Затем владелец предоставил
отчёт: «XML соответствует формату», проверены три объявления; отображённое
время принятия 04.10.2026 23:32:59, часовой пояс не указан. Все Id совпадают
с т29/т11/т12. Отметка «Отличное» рассчитана Avito по экрану/корпусу/батарее,
не заменяет входное Condition=Б/у и не является ошибкой.

Результат сохранён отдельно в `format-validator-evidence.json`; ожидаемый
SHA-256 локального файла совпадает с ранее зафиксированным. Сам отчёт не
показывает хеш загруженного файла, поэтому независимая проверка байтов
не заявляется. Формат принят отдельным валидатором, но фотографии, история,
модерация и фактическое принятие аккаунтом не проверены. Поле manifest
`official_xml_schema_validated=false` не отменяет этот положительный результат:
оно сохраняет ограничение полной схемной/кабинетной проверки. Production
schema/feed gates и publication approval не меняются автоматически.

`scripts/prepare_avito_xml_review.py` использует стандартный XML-парсер
ElementTree и повторно запускает существующие проверки по всему каталогу.
Не подменяет mapping.is_confirmed/status, не меняет production-генератор
и не является вторым live-feed engine. Новые пять тестов проверяют неизменность
источника, запрет обхода stock/identity/copy guards, приватные данные, выбор
1–3 SKU и необходимость подтверждённого состояния/RAM.

До будущего выкатa нужно согласовать минимальный XML с основным генератором:
его текущая поддержка скалярного BoxSealed не доказывает допустимость
отдельного тега без Set. Все production schema/feed gates остаются выключены.

Эта несовместимость локально устранена: основной генератор теперь блокирует
Set и BoxSealed как неподтверждённые поля и оставляет комплект в Description.
Даже BoxSealed=Нет в default_attributes mapping блокирует весь пригодный
пилот, а не пропускается незаметно. Это не меняет BoxSealed=Нет в XLSX.
Production не обновлялся. Порядок дальнейшей проверки:
[Проверка Перед Запуском Пилота](avito-pilot-activation-checklist.md).

После отдельного одобрения текста т12 пересобраны обе книги, пилотный JSON
и XML-пример. Проходят 70 Python и 27 feed тестов, всего 97. Новый тест
проверяет, что одобрение точного описания не разрешает публикацию.
Пункт о несогласованном тексте снят только для трёх пилотных устройств;
остальные ограничения manifest остаются в силе.
