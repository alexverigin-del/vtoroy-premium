# S3-резервирование коммуникаций ISVOI

## Назначение

Production-контур сохраняет каждые 30 минут:

- полный PostgreSQL dump в custom format;
- SHA-256-манифест всех файлов Directus;
- SHA-256-манифест приватных вложений коммуникаций;
- метаданные снимка и финальный маркер `_COMPLETE`.

Файлы находятся в неизменяемых пулах `objects-v2/directus` и `objects-v2/private`, где именем объекта служит SHA-256 содержимого. Новый снимок повторно загружает только новое или изменившееся содержимое, а не всю файловую библиотеку. Dump и манифесты соответствия исходных путей хэшам каждого запуска находятся в `snapshots/<backup-id>`.

Снимок пригоден для восстановления только при одновременном выполнении условий:

1. в `comm_backups` установлены `state = completed` и `external_verified = true`;
2. в S3 присутствует `snapshots/<backup-id>/_COMPLETE`;
3. SHA-256 файла `SHA256SUMS` совпадает со значением в `_COMPLETE`;
4. проверка файлов и `pg_restore --list` завершаются без ошибки.

## Закрытая конфигурация production

Бакет должен быть приватным. Публичная политика, CORS и собственный публичный домен для backup bucket не нужны. Репозиторий содержит только шаблон [`communications-backup.env.example`](../infra/communications/communications-backup.env.example).

На сервере используются два файла с владельцем `root:root` и правами `0600`:

- `/etc/isvoi/communications-backup.env` — пути и имя бакета;
- `/etc/isvoi/rclone.conf` — Access key и Secret key.

Ключи нельзя передавать в чат, включать в Git, журналы systemd или резервную копию проекта. При их регенерации Beget прежние ключи перестают работать, поэтому сначала обновляют закрытую конфигурацию сервера, затем немедленно запускают и проверяют контрольную копию.

## Установка и расписание

Установка выполняется на Ubuntu от root:

```bash
cd /opt/isvoi
bash scripts/install_communications_backup_on_host.sh
systemctl start isvoi-communications-backup.service
systemctl status isvoi-communications-backup.service --no-pager
systemctl start isvoi-communications-backup-health.service
systemctl list-timers 'isvoi-communications-backup*'
```

Основной timer запускается в `00` и `30` минут каждого часа с допустимой случайной задержкой до 90 секунд. Проверка свежести выполняется каждые 10 минут и переходит в ошибку при возрасте последней подтверждённой копии 45 минут. Целевой предел RPO в 60 минут тем самым контролируется заранее.

Скрипт не удаляет объекты из S3. Локальные staging-каталоги старше 48 часов удаляются только после успешной внешней проверки. Срок хранения и удаление внешних снимков задаются отдельной политикой после измерения фактического прироста и стоимости; до этого история накапливается.

## Проверка восстановления

Репетиция скачивает последний подтверждённый снимок, проверяет SHA-256, получает из S3 оба файловых пула и восстанавливает dump в одноразовый PostgreSQL 16 container с ограничением 768 МБ памяти и 0,75 CPU:

```bash
set -a
. /etc/isvoi/communications-backup.env
set +a
/usr/local/sbin/isvoi-communications-restore-rehearsal
```

Контейнер не подключается к сети и удаляется после проверки. Production-БД и production-файлы не изменяются. Успешный результат имеет вид `COMM_RESTORE_REHEARSAL_PASSED` и содержит идентификатор снимка, число таблиц и время проверки.

## Аварийное восстановление

Перед восстановлением production нужно остановить все исходящие workers и установить recovery hold. Затем выбрать только снимок с `_COMPLETE`, восстановить его в отдельной БД, сверить заявки, отказы, очереди и внешние операции. Исходящие отправки остаются выключенными до разбора операций со статусом `uncertain` или `partial`. Перенос восстановленной БД в production выполняется отдельной процедурой изменения состояния и не входит в автоматическую репетицию.

## Ограничение неизменяемости

Скрипт никогда не перезаписывает и не удаляет уже загруженные объекты: `rclone` вызывается с `--immutable`. Администратор аккаунта Beget или владелец ключа бакета технически может удалить данные. Поэтому backup bucket нельзя использовать как рабочее файловое хранилище, а доступ к панели и root-серверу должен быть защищён 2FA и отдельными учётными данными.
