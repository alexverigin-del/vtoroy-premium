# SLA первого ответа в коммуникациях

## Правило

Для каждого магазина хранится отдельная запись `comm_service_levels`. Начальные значения:

- часовой пояс — `Europe/Moscow`;
- рабочие дни — понедельник–воскресенье;
- рабочее время — 10:00–20:00;
- срок первого ответа менеджера — 10 рабочих минут;
- эскалация — через 15 рабочих минут.

Рабочие дни задаются числами ISO: понедельник — `1`, воскресенье — `7`. При создании обращения ядро рассчитывает и сохраняет два абсолютных срока в `comm_conversations`: `first_response_due_at` и `escalation_due_at`. Изменение графика влияет только на новые обращения и не переписывает историю.

Первым ответом считается первая часть ответа менеджера, которую площадка приняла. Автоприветствия и постановка сообщения в outbox норматив не закрывают. Если текст принят, а вложение отклонено, время первого ответа всё равно фиксируется; общий результат такого исходящего сообщения остаётся `partial`.

Старые обсуждения, созданные до установки этой версии, остаются со статусом `SLA не настроен`. Им не назначаются искусственные исторические сроки. При миграции открытые старые обращения нужно разобрать отдельно в рамках сверки.

## Изменение настроек

Настройки изменяет администратор для конкретного `store_id`. Пример для пятидневной недели:

```sql
UPDATE comm_service_levels
SET timezone = 'Europe/Moscow',
    working_days = ARRAY[1,2,3,4,5]::smallint[],
    workday_start = '10:00',
    workday_end = '20:00',
    first_response_minutes = 10,
    escalation_minutes = 15,
    enabled = true
WHERE store_id = '<UUID магазина>';
```

Схема запрещает пустой или неверный набор дней, конец смены до её начала, неположительный срок ответа и эскалацию раньше срока ответа. Для нового магазина запись с начальными значениями создаётся при применении схемы или при первом обращении.

## Отображение и эскалация

Очередь Directus вычисляет состояние относительно текущего времени:

- `Первый ответ по графику` — срок ещё не наступил;
- `Срок первого ответа истёк` — прошло 10 рабочих минут;
- `Требуется эскалация` — прошло 15 рабочих минут, уведомление ещё не поставлено;
- `Руководитель уведомлён` — уведомление поставлено в служебную Telegram-группу;
- `Первый ответ вовремя` или `Первый ответ с опозданием` — площадка приняла ответ менеджера.

Worker сначала обрабатывает входящее событие подключения. Когда входящей работы нет, он забирает одно просроченное обсуждение через `FOR UPDATE SKIP LOCKED`, создаёт карточку при необходимости, ставит уведомление с кнопками принятия и ответа и записывает событие `sla_escalated`. Транзакция и уникальный ключ события не позволяют двум workers создать две логические эскалации.

В первом выпуске автоматическое уведомление руководителя использует служебное назначение Telegram. Если оно выключено, обращение остаётся видимым как просроченное и будет проверено повторно. Следующие нормативы ответа и длительность ожидания клиента входят в последующее развитие.

## Проверки

`npm run communications:test` проверяет расчёт внутри смены, перенос через выходные, сохранение секунд, неверный график, фиксацию первого принятого ответа, частичную доставку и гонку двух workers за одной эскалацией. `npm run communications:ui:test` проверяет SLA-индикатор в настоящем Vue-модуле. Добавочная схема повторно применяется командой `npm run communications:local:setup`.
