# Studio UX: таблицы, навигация и формы

Статус: реализация локальная, Studio-миграции в production ещё не применены.
Первоначальная база аудита: `81a20ab`; итоговая проверка сделана на копии
production после отдельного релиза `c4d34a2`.

## Две Волны

1. `directus:setup:studio-workspace`: только метаданные. Понятные таблицы по
   умолчанию, рабочие Insights без тестовых заявок, отдельный список тестов,
   русские статусы, группы меню и нейтральное описание проекта.
   Права, публичные тексты и личные presets не меняются.
2. `directus:setup:studio-content`: внутренние названия страниц/блоков,
   отдельные примечание, дисклеймер, шаги, буллеты; группы форм и обратные
   связи правил Trade-in. Добавляется доступ к новым полям в уже существующих
   разрешениях. Их фильтры строк, роли и системные разрешения не меняются.

Это генераторы SQL, а не команды скрытого production apply. При `--rehearse`
они завершают транзакцию через `ROLLBACK`.

## Рабочие Сценарии

- Меню: Сайт и контент, Каталог, Магазины, Продажи, Trade-in, Блог, I СВОИ Club,
  Склад и импорт, Каналы продаж. Справочники, интеграции и складские подгруппы
  раскрываются по запросу. Имена таблиц и адреса Studio сохранены.
- Каталог начинается с фото, названия и SKU. Статус публикации, готовность и
  наличие остаются разными полями, но их значения показаны по-русски.
- Заявки и пять lead-панелей Insights исключают `is_test=true`. Полный QA-архив
  доступен в `Тестовые заявки`; специализированный Trade QA остаётся отдельно.
- В Trade-in открывайте версию цен, затем её диапазоны и вопросы с ответами.
  Самостоятельный вход в таблицы правил/диапазонов отфильтрован по опубликованной
  версии. UUID и технические ключи убраны из основных колонок.
- У страницы есть внутреннее название, не связанное с SEO. Два перехода ведут
  к действующим и отключённым блокам именно этой страницы. Полный список с
  порядком сохранён в свёрнутой группе. Присоединение чужих записей отключено.
- Согласие сгруппировано: баннер, окно настроек, категории, версия/срок,
  служебные данные. Магазин разделяет фактические контакты, оформление страницы
  и реквизиты продавца. Глобальные контакты обозначены как резервные.

Личные макеты имеют приоритет над ролевыми Defaults в Directus. Если после
выката остались старые четыре столбца товара, администратор может осознанно
сбросить настройки именно этой коллекции. Миграция не удаляет его личные
представления, ширины колонок и bookmarks.

Штатный `list-o2m` в Directus 11.17.4 не поддерживает постоянный фильтр уже
связанных записей: `options.filter` относится к выбору существующих строк.
Поэтому используются два нативных фильтрованных входа, а не фиктивные
дублирующие relations и не custom extension.

## Сохранность Контента

- `editor_label` нужен только Studio.
- `editor_note`, `editor_disclaimer`, `editor_steps`, `editor_proof` заполняются
  из текущего `page_sections.content` только при первом добавлении колонки.
  Никакие seed-файлы не читаются, исходный JSON не удаляется.
- Неиспользуемые конкретным блоком поля скрываются conditions. Настройка
  опирается на текущие ключи блоков, а не на выдуманный универсальный renderer.
- `null` у ещё не перенесённого поля означает совместимость со старым JSON.
  Пустая строка или `[]` означает намеренное удаление.
- Native repeater сохраняет `null` при удалении последней строки. Узкие
  PostgreSQL `BEFORE UPDATE OF` triggers нормализуют это в `[]`, а очистку
  примечания/дисклеймера в `""`. Изменение других полей этого не запускает.
- Адаптер Next и SQL-аудиты читают эффективный контент с одинаковым приоритетом.
  Аудиты создают только временную материализованную копию секций в своей сессии.
- Rich text обычного блока не предлагает HTML-код, медиа и H1. Примечания и
  дисклеймеры используют обычное многострочное поле, чтобы не добавлять HTML
  туда, где renderer выводит текст.
- Trade page audit проверяет структуру, обязательные тексты, CTA и согласие,
  а не совпадение маркетинговых фраз с seed. Юридический audit не ослабляется.

## Проверка До Выката

```bash
npm run directus:studio-ux:test
# Set DIRECTUS_AUDIT_SSH_TARGET to a staging host before rehearsal.
npm run directus:studio-ux:rehearse
npm run web:verify
```

Rehearsal создаёт отдельный PostgreSQL-контейнер со случайным именем, без сети
и портов, с лимитами 512 МБ RAM, 0.5 CPU и tmpfs для данных. Копия не исполняет
запросы внутри рабочего процесса PostgreSQL. Скрипт применяет обе волны дважды,
проверяет тексты, бизнес-данные, личные presets, неизменность permissions первой
волны и membership политик, удаление списков и повторный setup, затем весь
production SQL-набор. Контейнер удаляется при завершении; рабочая БД читается
только через `pg_dump`. Требуются SSH/Docker и не менее 1.5 ГБ доступной памяти;
вывод содержит только итоги проверок. После аварийного разрыва соединения
проверить контейнеры с префиксом `isvoi-studio-ux-`.

По умолчанию запуск на production-host теперь запрещён. Задайте staging через
`DIRECTUS_AUDIT_SSH_TARGET`. Исключение `--allow-production-host` допустимо только
в отдельно согласованном окне, без параллельного deploy/build. Даже при лимитах
контейнера предпочтителен отдельный staging-host.

Итоговый изолированный прогон: **23 SQL-аудита, 421 проверка, все прошли**.
Включены schema, Studio, catalog/v3, inventory, страницы, Files, права и Insights.
Проверены сохранение бизнес-данных и личных настроек, повторное применение и
очистка полей. Unit-тесты включены в `web:verify`. Публичный `smoke:copy` прошёл.

Предыдущий прогон через вычисляемую view затянулся перед сбоем VPS; в журнале
восстановления подтверждён OOM PostgreSQL, но конкретный SQL не установлен.
Проекцию заменили временной таблицей (расчёт один раз), добавили SQL timeout
45 секунд, lock timeout 3 секунды и отключили JIT. Оставшаяся старая тестовая БД
`isvoi_studio_ux_483de3ba3dc8` удалена; новые тестовые контейнеры также удалены.
Directus отвечает `ok`. Блокировка проверки снята; визуальный QA новых экранов
и revalidation после production apply остаются обязательными этапами выката.

## Порядок Выката

1. Сверить git, рабочее дерево и production. Сделать PostgreSQL/uploads backup
   штатным `scripts/backup_beget_directus.sh`. Сохранить metadata snapshot
   (collections, fields, relations, presets, panels, settings, permissions).
2. Сгенерировать и просмотреть SQL первой волны, применить с `ON_ERROR_STOP=1`.
   Перезапустить Directus без `FLUSHALL`; проверить новые Defaults и Insights.
3. Развернуть Next с совместимым адаптером. Затем применить вторую волну.
   Не запускать старые content setup/seed для «синхронизации» текстов.
4. Перезапустить Directus для metadata cache, выполнить существующую
   revalidation сайта. Изменения `page_sections` используют текущий cache Flow.
5. Запустить `directus:audit-studio`, `directus:audit:prod`,
   `directus:audit-homepage-copy`, `smoke:prod`, `smoke:images`, `smoke:copy`.
6. Войти Administrator на 1280 и 1440 px. Проверить поиск товара, оба списка
   блоков, открытие/сохранение блока, адрес магазина, версию Trade с вопросом
   и ответом, рабочие и тестовые заявки. Проверить переходы presentation-links.
   Снимки делать без персональных контактов заявителей.
7. На согласованной тестовой секции проверить изменение, очистку и сохранение
   примечания/списка; убедиться в обновлении сайта после revalidation. Проверить
   Editor/Advanced Editor на доступ к новым полям, не меняя публикационные права.
8. Зафиксировать commit, backup, фактические проверки и production-статус в
   операционной памяти.

До применения новой схемы проверки `studio-workspace`/`studio-content` на
production закономерно будут красными. Это не повод повторно запускать seed.

Единый порядок при развёртывании нового окружения: базовая схема/исторические
setup, затем `studio-workspace`, затем `studio-content`. Эти две миграции
являются последним слоем метаданных; старые UX setup не запускать после них.

## Откат И Границы

Первую волну откатывать адресным восстановлением metadata snapshot, без
восстановления всей бизнес-БД. Во второй волне поля аддитивные: не удалять их
и не восстанавливать JSON из seed. После редакторских правок в новых полях
нельзя откатить Next на версию без адаптера: это покажет устаревший JSON.
Нужен совместимый frontend либо отдельно проверенный CAS-перенос эффективных
значений в JSON с backup и проверкой текущих значений.

Не входят в этот релиз: изменение права Editor на публикацию и интеграции,
Draft Preview/версионирование страниц и собственное расширение Studio.
Заметка существующей Метрики «Шаблон выключен» является редакторскими данными:
её статус сверяется по полю `status`; исправление заметки делается отдельно в
Studio или guarded content patch, не общей metadata-миграцией.
