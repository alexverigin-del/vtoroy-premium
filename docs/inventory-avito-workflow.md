# ISVOI: товарный контур, маржинальность и Avito

Этот контур принимает полную выгрузку текущих остатков и отдельный файл
поступления. Он хранит закупку, полный serial/IMEI и unit-экономику только в
приватных коллекциях Directus. Публичный каталог обновляется исключительно
после ручного допуска позиции.

## Роли источников

- Полная выгрузка — источник текущего остатка и розничной цены.
- Поступление — исторический источник закупки, серийных номеров и плановой
  экономики. Оно не меняет остаток.
- Основной ключ — `source_system + Uuid`; код и штрихкод используются для
  проверки. Fuzzy-match допустим только как подсказка для несерийного товара.
- Серийная позиция считается совпавшей только при одинаковом serial и
  нормализованной идентичности товара. Расхождение создаёт blocker.

Исходные рабочие книги содержат коммерческие и идентификационные данные и не
коммитятся в git.

## Работа в Directus Studio

Оператор с ролью `ISVOI Inventory Manager` открывает `Товарные snapshot`
(`inventory_import_batches`):

1. Создаёт партию со стабильным именем и датой snapshot.
2. Загружает полную XLSX-выгрузку и при наличии XLSX поступления в папку
   `ISVOI Inventory Imports`.
3. Запускает Flow `ISVOI: проверить товарный snapshot`.
4. Проверяет счётчики и связанные `Проблемы импорта`. Полные serial/IMEI и
   себестоимость не переносятся в публичные коллекции.
5. Запускает apply только после разбора blocker-строк. Повторный apply
   идемпотентен.

Если ранее известная позиция исчезла из полной выгрузки, dry-run показывает
`missing_from_snapshot`, но не меняет данные. Обнуление разрешается только
после включения `Разрешить обнуление отсутствующих позиций`; при этом товар
получает нулевой остаток, а активное канальное объявление возвращается в draft.

## Допуск в Catalog V3

Новая строка остаётся только в `inventory_items` со статусом `pending` или
`blocked`. Для создания/обновления черновика `products` Inventory Manager
должен одновременно:

- установить `authenticity_status = verified` или `not_required`;
- установить `review_override = true`;
- заполнить `review_note` фактическим основанием проверки;
- установить `eligibility_status = eligible`.

Созданный товар всегда получает `status = draft` и
`content_status = needs_photo`. Публикация требует обычного QA Catalog V3:
категории и бренда, положительного остатка, карточного/основного изображения,
гарантии; для б/у техники — Passport, grade, батареи и даты диагностики.

Replica, неподтверждённый бренд, Mini iPhone-подобные устройства и товары с
identity-конфликтом не допускаются. Значение `ассорт.` требует разделения
вариантов либо режима продажи по запросу.

## Unit-экономика

`channel_cost_profiles` хранит подтверждённые ставки комиссии, эквайринга,
налога, возвратного резерва, продвижения, доставки и прочих переменных затрат.
Read-only представление `product_unit_economics` рассчитывает gross profit,
gross margin, variable cost, contribution и contribution margin.

Начальные профили `site` и `avito` имеют нулевые ставки и
`is_confirmed = false`. Такие расчёты считаются неполными и не используются для
ценового решения, пока Inventory Manager не подтвердит ставки.

## Avito

`channel_category_mappings` отделяет внутренние категории сайта от значений
официального шаблона Avito. Для каждой активной `product_categories` создаётся
начальная строка канала `avito`; внутренний slug (`smartphones`, `watches`,
`smart-electronics` и другие) никогда не экспортируется как категория Avito.
Категория сайта может иметь несколько mapping с разными стабильными
`mapping_key`: это нужно для широких разделов вроде `smart-electronics`, где
смарт-очки, камеры и фотопринтеры могут относиться к разным веткам Avito.

После текущей сверки товарной структуры:

- часы и браслеты используют внутреннюю категорию `watches`;
- смарт-очки входят в `smart-electronics`, отдельная публичная категория для
  одной позиции не создаётся;
- кабели из складской группы «Зарядные устройства» относятся к `chargers`;
- пустые активные категории остаются в Directus, но не появляются на сайте и
  не могут попасть в Avito без товара и подтверждённого mapping.

Inventory Manager заполняет в mapping точные `Category`, при необходимости
`GoodsType` и код категории, общие атрибуты, а также дату/версию скачанного
официального шаблона. `is_confirmed` включается только после проверки XML.
Предзаполненных догадок о значениях Avito нет: начальные строки создаются
неподтверждёнными.

`product_channel_listings` хранит стабильный `external_id` вида
`isvoi-<Uuid>`, ссылку на category mapping, ручную канальную цену и атрибуты
выбранного шаблона. Старое поле `category_code` сохранено только для обратной
совместимости и feed его не использует. Endpoint
`/integrations/avito/feed.xml`:

- закрыт флагом `AVITO_FEED_ENABLED=0` до завершения пилота;
- отдаёт только активные объявления опубликованных и готовых товаров с
  положительным остатком и опубликованным изображением;
- возвращает `X-Robots-Tag: noindex, nofollow` и `Cache-Control: private,
  no-store`;
- не включает закупку, маржу, полный serial/IMEI и внутренние заметки.
- исключает объявления без активного подтверждённого category mapping;
- объединяет общие атрибуты mapping с атрибутами конкретного объявления.

До включения нужно экспортировать официальный шаблон нужной категории из
бизнес-кабинета Avito, зафиксировать его версию и проверить XML по этой схеме:
[шаблоны автозагрузки](https://www.avito.ru/autoload/documentation/templates)
и [проверка XML](https://autoload.avito.ru/format/xmlcheck/).
Пилот — три подтверждённых б/у смартфона одной категории. Расширение возможно
после принятия фида и 72 часов без рассинхронизации.

## Команды

```bash
npm run directus:inventory:test
python scripts/inventory_pipeline.py --inventory /path/inventory.xlsx \
  --receipts /path/receipt.xlsx --batch 2026-08-10-store-snapshot
npm run directus:setup:inventory
INVENTORY_IMPORT_WEBHOOK_SECRET=... npm run directus:setup:inventory-flow
npm run directus:audit-inventory
npm run directus:avito:test
```

Перед production-миграцией обязателен локальный VPS backup PostgreSQL и
uploads. Offsite backup остаётся отдельным отложенным пунктом.
