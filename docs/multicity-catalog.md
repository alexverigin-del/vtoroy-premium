# Мультигородской каталог I СВОИ

## Каноническая модель

- `isvoi.ru` остаётся единственным индексируемым доменом и общей точкой checkout.
- Городские хабы живут по адресу `/{city}`; первый город — `/belgorod`.
- Карточка товара всегда каноническая: `/product/{slug}`.
- Городской поддомен используется только как короткий 301-вход.
- Геоподсказка не перенаправляет автоматически и не меняет скрытно цену.

## Directus

`store_locations` хранит публичные данные точки: адрес, контакты, часы, карту,
фотографии, способы получения и локальные SEO-поля. `product_offers` связывает
товар с точкой и становится источником цены, остатка, локального SKU, срока
подготовки, способов получения и доступности Яндекс Пэй/Сплит.

Пока действует dual-read, каталог сначала использует предложение выбранного
города, затем предложение с межгородской доставкой и только после этого legacy
поля товара. Legacy-поля нельзя удалять до отдельного стабильного релиза.

В Studio редакторы работают с папкой «Магазины, адреса и наличие». Внутри две основные
точки входа: «Магазины и города» для адреса, контактов, способов получения и
контента городской страницы; «Предложения магазинов» для локальной цены,
остатка и доставки. Начинайте с представлений «Требуют внимания», «Белгород»,
«В наличии» или «Доступно с доставкой». Публичное предложение требует
локальный SKU, цену, видимый статус и хотя бы один способ получения. Сплит
нельзя включить без Яндекс Пэй.

Для первого города действующие Editor и Advanced Editor имеют доступ к
предложениям сети. До добавления второго города нужно создать отдельную роль
городского редактора с item-level filter по `location`; нельзя имитировать
изоляцию только пресетом Studio.

## Маршруты

- `/stores` — список опубликованных точек;
- `/belgorod` — городской хаб;
- `/belgorod/catalog` — каталог с приоритетом белгородских предложений;
- `/belgorod/catalog/tech` и `/belgorod/catalog/accessories` — направления;
- `/belgorod/catalog/category/{slug}` и `/brand/{slug}` — локальные срезы;
- `/belgorod/delivery` — локальные условия получения;
- `/belgorod/contacts` — постоянный редирект на городской хаб `/belgorod`;
- `/contacts` — постоянный служебный вход на список `/stores`;
- `/store` и `/stores/belgorod` — постоянные редиректы на `/belgorod`.

Адрес, карта, часы, способы связи и реквизиты уже выводятся в общем footer и
на городском хабе. Отдельная contact-page не публикуется, пока у неё нет
уникального содержания: схемы входа, парковки, фотографий ориентира,
доступности или записи на визит. Contact redirects не включаются в sitemap.

## Геоподсказка

Приоритет выбора: город в URL, cookie `isvoi_city`, известный город из
edge-заголовка, нейтральный режим. Endpoint `/api/location-hint` принимает
только allowlist опубликованных городов. Роботам и пользователям без выбора
отдаётся стабильный сетевой каталог.

## Поддомен Белгорода

DNS `belgorod.isvoi.ru` должен указывать на публичный ingress сайта. TLS-сертификат
обязан включать этот hostname. Middleware принимает только allowlist городских
hostnames и отвечает 301 на основной домен; отдельные sitemap, cookies и контент
на поддомене не создаются. Неизвестные поддомены также переводятся на основной
домен без создания городского сайта.

## Выпуск и проверка

1. Создать и проверить backup PostgreSQL и uploads.
2. Применить `npm run directus:setup:multicity` и revalidation setup.
3. Выполнить `npm run directus:audit:multicity` и общий production audit.
4. Собрать Next.js и перезапустить только web-процесс.
5. Проверить городские URL, canonical, sitemap, JSON-LD и ручной выбор города.
6. Проверить 301 с поддомена после готовности DNS и TLS.
7. Убедиться, что обновление offer инвалидирует глобальный каталог, городской
   каталог и карточку товара.

Удаление legacy цены и остатка из `products`, городские роли и подключение
checkout к `offer_id` выполняются отдельными forward-only релизами.
