# Telegram: обращения, поддержка и подписки

## Выпуск

Версия расширяет действующий production-бот `@isvoi_help_bot`. Канал не подключается. Управление выполняется в Directus, а отправка остаётся в одном long-polling worker.

Флаги Directus:

```env
ISVOI_TELEGRAM_ENABLED=true
ISVOI_TELEGRAM_CONVERSATIONS_ENABLED=true
ISVOI_TELEGRAM_NOTIFICATIONS_ENABLED=true
```

Флаг включён в production после миграции `scripts/setup_directus_telegram_notifications_sql.mjs`. Настройка `telegram_bot_settings.notifications_enabled` служит вторым выключателем. Первый выпуск работает с `pilot_mode=true` и разрешённым Telegram ID `65092546`; остальные пользователи видят сообщение о закрытом пилоте и не могут подписаться.

Production-пилот выпущен 5 сентября 2026 года на feature-коммите `e49484b4dccaef304dac87dacad3e0624173758c`; текущий production-коммит `a45255a` добавляет retry для кратких сетевых сбоев Telegram API. Резервная копия выпуска: `/opt/isvoi/backups/telegram-notifications-20260905T164908332Z`. Release gate, полный `web:verify`, изолированный PostgreSQL/Directus-контракт, применение и повторная проверка нативного профиля Telegram, lease worker и HTTP smoke сайта прошли.

Перед выпуском обязательны:

```bash
npm run telegram:build
npm run telegram:test
node scripts/rehearse_telegram.mjs --production
npm run web:verify
```

После локального коммита пакет готовится командой:

```bash
npm run telegram:release:notifications:prepare -- work/outputs/telegram-notifications-release-<id>
```

Скрипт production-выпуска имеет режимы `check`, `enable`, `disable`. `enable` делает резервную копию PostgreSQL и env, повторяет тесты, применяет схему, включает только закрытый пилот, заполняет нативный профиль Telegram и проверяет сайт и lease worker. `disable` выключает кампании и отменяет все ожидающие маркетинговые сообщения, сохраняя заявки и переписку.

## Пользовательский процесс

Общая ссылка `https://t.me/isvoi_help_bot?start=site` записывает источник `site`, показывает приветствие и пять действий, но не создаёт заявку. Одноразовые ссылки после форм продолжают привязывать конкретную заявку.

Команды личного чата:

- `/start` — главное меню;
- `/new` — новое обращение;
- `/dialogs` — активные заявки;
- `/news` — текущее состояние подписок;
- `/help` — информация о боте.

Первый содержательный текст или фотография без выбранной категории создаёт заявку `support` и сразу сохраняется в её истории. Сообщение не нужно отправлять повторно. Для заявок без города используется действующий маршрут с `accept_unscoped=true`, сейчас это Белгород.

Ссылку на бот сайт показывает в карточке контактов города и в футере. Подпись и URL хранятся в `site_settings.support_telegram_label` и `site_settings.support_telegram_url`.

## Согласия и данные

`telegram_bot_settings` хранит приветствие, описание, текст и версию согласия, часовой пояс, разрешённое окно, недельный лимит и feature flags. `telegram_notification_topics` содержит три темы: новые поступления, снижение цен, новости и акции.

`telegram_subscriptions` хранит текущее состояние. `telegram_subscription_events` является неизменяемым журналом согласий, отказов и блокировок. Существующие пользователи не получают подписку автоматически. При отказе ожидающие задания выбранной темы сразу переходят в `cancelled`.

Public не получает разрешений к настройкам, подпискам, журналу, кампаниям и outbox. Политика `ISVOI Editor` может читать показатели, создавать и редактировать только `draft`/`review`. Поля подтверждения ей недоступны. Администратор запускает кампанию через Manual Flow.

До публичного включения необходимо утвердить текст согласия, его версию и срок хранения журнала. Текущая версия `pilot-2026-09` предназначена только для закрытого пилота.

## Кампании в Directus

Коллекция `telegram_campaigns` поддерживает один текст, одно изображение из `directus_files`, одну CTA-кнопку, необязательную связь с товаром и неперсональные UTM. Произвольный URL фотографии не хранится и не принимается. CTA допускает только HTTPS на `isvoi.ru` и его поддоменах.

В Studio добавлены действия:

- «Telegram: отправить тест себе»;
- «Telegram: передать на проверку»;
- «Telegram: подтвердить и запустить».

Тест получает только разрешённый участник пилота, Telegram ID которого связан с текущим Directus-пользователем через `telegram_staff`. После подтверждения worker атомарно сохраняет снимок содержания и создаёт снимок получателей в outbox. Уникальность `campaign_id + session_id` не допускает повторной отправки при повторном запуске. После создания снимка содержательные поля кампании защищены PostgreSQL-триггером; исправление делается в копии.

В Directus созданы представления «Черновики», «На проверке», «Отправляются», «Завершены», «Ошибки доставки», «Активные подписки», «Отказы и блокировки».

Тип назначения `channel` зарезервирован схемой, но перевод такой кампании в запуск отклоняется. Для канала потребуется отдельный проверенный chat ID, права бота и независимый результат публикации.

## Доставка

Worker сначала обрабатывает карточки заявок, ответы и служебные сообщения. Кампании выбираются после них. Общая скорость остаётся одной отправкой примерно за 3,2 секунды.

Маркетинговые задания отправляются только с 10:00 до 20:00 по `Europe/Moscow`. Вне окна `due_at` переносится на следующее открытие. При двух успешных маркетинговых отправках за скользящие семь дней следующий получатель получает `suppressed_frequency`; сообщение позже не досылается.

Состояния доставки:

- `pending`, `in_flight` — очередь и текущая попытка;
- `done` — Telegram принял сообщение, это не признак прочтения;
- `blocked` — Telegram вернул 403, подписка блокируется;
- `failed` — определённая постоянная ошибка;
- `uncertain` — результат неизвестен, автоматический повтор запрещён;
- `suppressed_frequency` — недельный лимит;
- `cancelled` — отказ или выключение функции до отправки.

`429` возвращает задание в очередь на `retry_after`. Ответы по заявкам не входят в недельный лимит.

## Проверка пилота

После включения участник пилота открывает общую ссылку, проверяет отсутствие пустой заявки, отправляет вопрос без категории и подписывается на каждую тему. Редактор создаёт по одной тестовой кампании, запускает «Отправить тест себе», передаёт на проверку. Администратор подтверждает. В Telegram и Directus проверяются текст, фото, CTA, состояния outbox и счётчики кампании. Затем участник отключает подписку; новое ожидающее сообщение должно перейти в `cancelled`.
