## Решение

Три разных действия, без объединения под одним «Назад»:

| Действие | Поведение |
| --- | --- |
| Назад | Предыдущий шаг своей ветки, ответы и введённые контакты остаются в текущей сессии |
| Изменить | Возврат к конкретной группе заполненных данных |
| Начать заново | Диалог подтверждения, затем новая локальная сессия оценки |

Внутри калькулятора: строка навигации, progress, содержание шага, один основной CTA. Глобальную шапку сайта не дублировать. «Назад» слева, «Начать заново» справа; сброс не размещать рядом с кнопкой отправки. На чистом первом шаге обе ссылки отсутствуют. После отправки — «Оценить другое устройство», без повторной отправки прежней заявки.

В прототипе клик по модели N08 открывает заполненный пример N01. Клик по карточке оценки N03 демонстрирует истечение срока N10. Это условные демонстрационные переходы, не требования к кликам в production.

## Данные и пересчёт

- Обычный возврат не очищает ответы и не требует валидности незавершённого текущего шага.
- Если исходные данные не менялись, не создавать лишнюю оценку.
- Изменение модели, конфигурации или влияющих на оценку ответов инвалидирует старый результат. Новый диапазон рассчитывает только сервер.
- При исправлении модели заново подтвердить сведения о состоянии. Для другого физического устройства использовать новую оценку.
- Смена сценария, магазина или целевого предложения сама по себе не меняет оценку сдаваемого устройства; наличие предложения проверяется повторно.
- Истечение срока: обновить оценку с сохранёнными ответами, не отправлять пользователя заполнять всё заново.
- Ручная оценка / safety-stop допускают исправление ошибочного ответа, но не обходят серверные ограничения.
- Пустой обмен возвращает к выбору сценария; исчезнувшее предложение — к подбору доступного товара.

## Сброс

Диалог явно сообщает, что заполненные ответы и результат будут убраны, а отправленные заявки сохранятся. Два действия: «Продолжить текущую оценку» и «Начать заново».

При подтверждении очистить модель, память, ответы, локальный quote, сценарий, выбранное предложение, контакт, комментарий, согласие и пожелания по визиту. Город сайта можно сохранить как общую настройку. Серверные quotes и leads не удалять.

Новая сессия получает новый runId и новый ключ отправки. `sessionStorage` хранит только неперсональные данные; телефон, Telegram, комментарий и согласие туда не писать. Удалять только ключи калькулятора, не весь storage сайта.

`history.state` синхронизируется без параметров в URL. Старые Back/Forward-записи после сброса не должны восстанавливать прошлую оценку: проверять идентификатор сессии. Один `replaceState` не удаляет остальные записи браузерной истории.

Отменять запросы по возможности и игнорировать поздние ответы предыдущего runId. Во время отправки заявки сброс блокировать до известного результата: отмена запроса не доказывает отмену записи на сервере. Retry использует прежний ключ идемпотентности, новая оценка — новый.

## Доступность и проверка

- Возврат и продолжение доступны клавиатурой, цели не менее 44×44 px.
- После перехода фокус на заголовке шага; после отмены сброса — на его инициаторе.
- Диалог удерживает фокус, закрывается по Esc без потери данных; начальный фокус на безопасном действии продолжения.
- Изменение диапазона объявляется через aria-live; ошибки связаны с полями.
- Учитывать reduced motion, мобильную клавиатуру, safe-area и sticky CTA.
- Проверить возврат всех полей, обе ветки N06, отсутствие лишнего пересчёта, инвалидирование оценки, отмену/подтверждение сброса, Back/Forward после сброса, запоздалые API-ответы, retry, истечение и новую оценку после отправки.

## Границы проверки

Проверены структура новой страницы, узлы переходов и визуальные снимки макетов. Это не браузерный E2E-тест и не проверка доступности работающего сайта. Цены, товар, контакт и номер заявки в макетах — демонстрационные примеры, не актуальный каталог/тарифы и не реальные заявки. Чекбокс N06 показан выбранным только для иллюстрации заполненного состояния; при настоящем новом входе согласие должно быть пустым. Действующие юридические тексты, антиспам и валидация production сохраняются.

Для реализации следовать действующему контракту формы. Функциональность навигации не деплоилась и production не менялся в этой задаче.

### Что работает в коде

- Строка «Назад / Начать заново» над progress, отдельные «Изменить ответы / Изменить устройство»; на чистом старте навигация скрыта.
- Возврат использует историю своей ветки, не добавляя бесконечную цепочку новых обратных переходов. После перехода фокус получает H3, а прокрутка оставляет видимой и строку навигации. Reduced motion сохранён.
- Отпечаток модели, памяти и ответов связан с quote. Неизменённые данные повторно используют действующий результат; изменения его инвалидируют. Смена модели очищает память и ответы для повторного подтверждения состояния.
- Подтверждённый сброс очищает локальную оценку, контакты, свободный текст, согласие, выбранный товар и пожелания по визиту. Другие ключи sessionStorage, серверные заявки и quotes не удаляются.
- Новый runId также служит стабильным ключом отправки: retry/восстановление незавершённой сессии сохраняют его, новая оценка получает новый. Старые Back/Forward-записи не восстанавливают прежнюю сессию; после успеха браузерный возврат не открывает повторную отправку.
- Запоздалые ответы отменённых запросов оценки/каталога игнорируются. Во время отправки заявки поля, возвраты и сброс заблокированы; браузерный Back не переключает незавершённую отправку на другой шаг.
- Native dialog имеет название и описание, безопасный начальный фокус, явный цикл Tab/Shift+Tab, Esc без сброса и возврат фокуса к инициатору. В коде безопасное действие «Продолжить текущую оценку» сделано основным; это намеренное уточнение иерархии кнопок относительно макета.
- Истечение quote сохраняет ответы для пересчёта; `product_unavailable` возвращает к свежему каталогу с сохранением контакта в памяти. После reload обмен заново получает предложения, а не доверяет сохранённому остатку.
- Общий `useLeadIntake` поддерживает появление/удаление и повторный монтаж Turnstile на разных шагах, очистку устаревших callback и защиту от двойной отправки. Контракты остальных форм совместимы.

### Закрытие bundle gate · 31.08.2026
