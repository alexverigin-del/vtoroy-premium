# Trade-in: закрытая QA-приёмка draft

Закрытый контур доступен по `/trade/qa` только при `TRADE_QA_ENABLED=1`, корректном `TRADE_QA_SECRET` и действующей HttpOnly-сессии. Публичный `/trade` и публичные Trade-in API не включаются: `TRADE_WIZARD_ENABLED` должен оставаться `0`.

## Безопасность

- Код доступа содержит не меньше 32 символов и хранится только в server env или корпоративном менеджере секретов.
- Код передаётся POST-запросом и никогда не добавляется в URL.
- QA-cookie подписан HMAC-SHA256, имеет `HttpOnly`, `Secure`, `SameSite=Strict` и действует 8 часов.
- Вход ограничен пятью попытками за 15 минут на IP.
- `/trade/qa` закрыт от индексации через metadata, `robots.txt` и `X-Robots-Tag`; ответы не кешируются.
- QA-cookie открывает только draft-контекст Trade-in. Он не даёт доступ к Directus или системным коллекциям.

## Изоляция данных

Миграция `directus:setup:trade-qa` добавляет `is_test` в `trade_quotes`, `trade_events` и `leads`. Значение выставляет сервер, клиент не может снять его самостоятельно.

- QA-оценки читаются и создаются только при действующей QA-сессии.
- Публичный обмен и обычная заявка отвергают QA quote, даже если известен UUID.
- Тестовые заявки получают номер `QA-YYMMDD-NNN` и отдельный Studio-фильтр «Trade-in · тестовые заявки».
- QA-события исключаются из клиентской воронки по `is_test=true`.
- Для проверки формы используйте только контролируемый тестовый телефон или Telegram. Менеджер не должен связываться с такими заявками.
- QA использует отдельные ключи `sessionStorage`, поэтому draft quote не восстановится в будущем публичном мастере.

## Включение QA без включения калькулятора

1. Сделать production backup PostgreSQL и uploads.
2. Выполнить rollback-rehearsal `directus:setup:trade-qa`, затем применить его.
3. Запустить `bash scripts/configure_trade_qa_env.sh`. Скрипт создаёт или сохраняет секрет, включает только QA и принудительно оставляет `TRADE_WIZARD_ENABLED=0`.
4. Перезапустить Directus для permission cache, собрать web и перезапустить PM2.
5. Выполнить `directus:audit:trade-mvp` и `smoke:trade-qa`. Для smoke передать `TRADE_QA_SECRET` через окружение, не через аргументы или URL.
6. Повторно проверить без cookie: `/api/trade/config` и quote возвращают fail-closed `503`, на `/trade` мастер отсутствует.

Отключение QA: установить `TRADE_QA_ENABLED=0`, перезапустить web. Существующие тестовые записи сохраняются для аудита и остаются помеченными `is_test=true`.

## Чек-лист приёмки T01–T11

- Пять моделей и все 19 вариантов памяти.
- Хорошее состояние, повреждения корпуса и объясняющие факторы.
- Ручная оценка: устройство не включается, неисправный экран/функция, ремонт неизвестен.
- Safety-stop аккумулятора.
- Продажа, консультация по комиссии и обмен.
- Белгородский остаток, межгород, пустой обмен и исчезновение offer перед заявкой.
- Повторная отправка возвращает тот же `QA-...` номер.
- Back/restore, retry, мобильная клавиатура и sticky CTA.
- Срок quote до 23:59 МСК, истечение и пересчёт.
- После завершения QA публичный `/trade` остаётся без калькулятора.
