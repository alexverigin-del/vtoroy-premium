# Яндекс: SEO и IndexNow

## Границы

Основной индексируемый сайт — `https://isvoi.ru`. Club остаётся в пилотном
`noindex`; Trade QA, API, интеграционные фиды и lead-intake не отправляются.
Согласие на Метрику не меняется. IndexNow работает на сервере, без cookies,
браузерных скриптов, персональных данных, Directus-токенов в запросах к Яндексу.

IndexNow сообщает об изменениях, но не гарантирует индексацию или рост позиций.
Первичная передача всех существующих страниц выполняется через Sitemap, не
массовой отправкой старых URL в IndexNow.

## SEO-контракт

- `/stores` и `/{city}/delivery` имеют собственные canonical, title, description
  и OpenGraph URL. Город и условия остаются данными Directus; никаких новых
  обещаний о доставке, возврате или гарантии код не добавляет.
- Пустые координаты не превращаются в нули. Geo публикуется только для полной
  числовой пары в допустимом диапазоне; заглушка `0, 0` не публикуется.
- `lastmod` в Sitemap берётся только из существующей даты изменения. При
  отсутствии даты, некорректной или будущей дате поле опускается, а не заменяется
  временем генерации. Для статических/агрегатных страниц даты не выдумываются.
- Description товара начинается с его полного названия, затем содержит
  опубликованные грейд, батарею, гарантию и краткое описание. Значения из
  Directus не перезаписываются. Серийные номера/IMEI не используются.
- Тексты системных SEO-шаблонов проверяются через content-ownership baseline.

## Как работает очередь

1. Существующий защищённый `/api/revalidate/site-content` сначала проверяет
   секрет и сбрасывает кеш, затем атомарно записывает новый маркер `dirty.json`.
   Это охватывает имеющийся Directus event Flow и цепочку отложенной публикации
   блога; менять права/схему/Flow не требуется.
2. Systemd timer запускает worker раз в минуту. Неизменившийся маркер пропускает
   сканирование; раз в час выполняется сверка даже без события — для импортов,
   прямых SQL-обновлений и восстановления после неудачной записи маркера.
3. Worker проверяет health Directus, Sitemap, robots и публичный HTML. Хеширует
   основной контент, метаданные, изображения/ссылки и JSON-LD; не учитывает
   React flight, случайные ID, CSS-классы и имена JS-сборок.
4. Сравнивает отпечатки с `state.json`. Отправляет только новые/изменившиеся URL
   или подтверждённое исчезновение ранее известного публичного URL. Один факт
   отсутствия в Sitemap недостаточен: нужен 404/410, проверенный редирект,
   `noindex`, смена canonical или запрет robots. Удаление подтверждается двумя
   успешными сверками с интервалом минимум 60 секунд.
5. Состояние подтверждается только после HTTP 200/202 от IndexNow. При ошибке
   предыдущие отпечатки остаются, работает экспоненциальная задержка и
   `Retry-After`. Новое редакторское событие не обходит эту паузу.
   HTTP 202 означает ожидание проверки ключа, а не индексацию.

Новые `noindex`/неканонические URL не отправляются. CMS outage, неполный HTML,
невалидный Sitemap, 404 страницы внутри текущего Sitemap, таймауты и массовое
исчезновение более `max(5, 20% предыдущих URL)` останавливают проход. Массовое
снятие публикации требует проверки оператором; не сбрасывать state вслепую.

Текущий защитный лимит — 500 URL суммарно (с учётом старых). При росте каталога
лимит повышать вместе с пагинацией/пакетированием и нагрузочными проверками.
Один scan ограничен примерно девятью минутами; параллельно идут не более трёх
чтений страниц. Lock исключает параллельные workers и восстанавливается после
15 минут. Сбой worker не влияет на сохранение редакторского контента.

## Подготовка локально

```bash
npm run web:test:seo-indexnow
npm run web:verify
npm run web:smoke:seo
```

Тесты worker полностью подменяют HTTP и не обращаются к production/Яндексу.
HTTP smoke запускает копию compiled build во временном каталоге и loopback CMS,
чтобы fixture-страницы никогда не записывались в ISR-кеш рабочей сборки.
`INDEXNOW_ENABLED=0` по умолчанию. Ключ не хранится в Git, публичный key endpoint
при выключенном механизме отвечает 404. `indexnow:preview` не отправляет запросы
IndexNow и не меняет baseline; читает публичный сайт и временно берёт lock.

## Включение при отдельно разрешённом выкате

1. Обычная проверка Git/production и резервная копия. Выпустить приложение и
   проверить canonical, отсутствие `0,0`, Sitemap и регрессию согласия Метрики.
2. Создать `/opt/isvoi/var/indexnow` владельцем `deploy`, режим `0700`. Сохранить
   новые env-поля в `apps/web/.env.local`: `INDEXNOW_ENABLED=1`,
   `INDEXNOW_STATE_DIR=/opt/isvoi/var/indexnow`, `INDEXNOW_KEY` — случайный ключ
   из 32 байт в hex. Не использовать Directus/ревалидационный секрет как ключ.
   Значения должны совпадать у Next и worker. Перезапустить Next штатно.
3. Проверить `https://isvoi.ru/indexnow-key.txt`: HTTP 200, UTF-8 text/plain,
   точное значение ключа, без редиректа/HTML. Этот файл подтверждает владение
   хостом; `keyLocation` всегда передаётся в payload.
4. Из `/opt/isvoi` выполнить `npm run indexnow:initialize`. Создаст baseline,
   **ничего не отправляя**. Повторная инициализация существующего состояния
   запрещена. Затем `npm run indexnow:preview` — список изменений должен быть
   пустым, если контент не менялся.
5. Установить `infra/systemd/isvoi-indexnow.service` и `.timer` в
   `/etc/systemd/system/`, выполнить `systemctl daemon-reload` и
   `systemctl enable --now isvoi-indexnow.timer`. Проверить реальный путь Node
   (`/usr/bin/node`) и env-файла перед включением. Это новый системный сервис,
   поэтому устанавливать только в рамках явно разрешённого выката.
6. После согласованного изменения публичного контента проверить journal,
   `lastSuccessAt`, счётчик `submitted` и HTTP 200/202. Не менять товар/цену ради
   теста и не делать тестовую заявку. Ошибки: `journalctl -u isvoi-indexnow`.

`state.json` и `dirty.json` — постоянные эксплуатационные данные, не артефакты
сборки. Их сохраняют между выкатами. Штатный `backup_beget_directus.sh` дополнительно
копирует `state.json` как `indexnow-state.json` с SHA-256; lock и ключ не копируются.
Для нестандартного пути передайте `INDEXNOW_STATE_DIR` в backup. В этих файлах только
публичные URL, хеши и технические отметки времени; никакого HTML, контактов или
содержимого Directus. При потере state worker остановится, потребуется
осознанная новая инициализация; изменения за потерянный интервал не восстановятся.
Текущий механизм рассчитан на один VPS с общей файловой системой Next/worker.
При горизонтальном масштабировании потребуется общее хранилище и distributed lock.

Отключение: остановить timer и выставить `INDEXNOW_ENABLED=0` у Next, затем
перезапустить приложение. State сохранить для последующего продолжения.

## Что проверяется отдельно в Вебмастере

- Sitemap `https://isvoi.ru/sitemap.xml` добавлен и обработан без ошибок.
- Правильный счётчик привязан к сайту, включён «Индексирование → Обход счетчиком».
- Регион соответствует фактической работе магазина, нет нарушений/угроз.
- После исправлений точечно отправлены важные страницы на переобход, проверены
  канонические URL и статусы исключения. HTTP 200 на сайте не доказывает наличия
  страницы в индексе. Вход и изменения в кабинете не автоматизируются этим кодом.
